# I1.2.5 — Convergence gate + anti-gaming guard

Implement the quantitative convergence gate (Trait ④), but prevent the gaming
where the model stops merely by self-declaring that it has "converged"
(critique C3).

## Background
If the stop condition is purely self-assessed, there is an incentive to lower
scores in order to finish faster. → Strengthen the gate with an independent
critique sign-off + objective signals (spec §4.4).

## Stop conditions (all MUST be met)
1. Run-level weighted ambiguity ≤ threshold (config)
2. Testable acceptance criteria for every active component — **redteam-critic sign-off is required**
3. Zero unresolved blocking open questions
4. At least 1 round complete AND zero new ambiguity in the previous round
